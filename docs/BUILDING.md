# Building Warnel Chawpiovs

This document covers building the Windows and HTML5 versions with Godot 3.5.3, running the automated test suite, and the verification record so far.

Placeholders used below:
- `<godot>`: path of the Godot 3.5.3 editor executable
- `<project>`: path of this repository
- `<output>`: a folder of your choice for build outputs

---

## 1. Development environment

| Item | Version / setting |
|---|---|
| Godot editor | **3.5.3 stable** (`3.5.3.stable.official`), standard build (not Mono) |
| Export templates | **3.5.3 stable**, the exact same version as the editor |
| Project format | Godot 3.x (`config_version=4` in `project.godot`) |
| Main scene | `res://src/wc/MainMenu.tscn` |

Installing the export templates: in the editor, **Editor > Manage Export Templates**, then install the 3.5.3 templates. Exporting fails if the template version differs from the editor version.

Notes:
- The repository may have been saved by a newer 3.x editor. Opening it with 3.5.3 can rewrite some settings automatically, for example removing the `"canceled"` input field in `project.godot` or 3.6-only keys in `export_presets.cfg`. These changes are not needed for building and should not be committed. Check `git status` after opening the project in the editor.
- `project.godot` enables the `addons/Holepunch` editor plugin. The multiplayer lobby (`src/wc/lobby/MultiplayerLobby.tscn`) references `holepunch_node.gd` directly.

## 2. Windows build

### Preset (`export_presets.cfg`, `[preset.1]` "Windows Desktop")

| Setting | Value | Meaning |
|---|---|---|
| `export_path` | `./WC.exe` | Default output is the repository root. `WC.exe` and `WC.pck` are listed in `.gitignore` |
| `binary_format/64_bits` | `true` | 64-bit build |
| `binary_format/embed_pck` | `false` | The game data is a separate `WC.pck` file |
| `include_filter` | `*.json, *.txt` | **Required.** Card data and scripts (`Sets/*.json`) are not Godot resources and are only exported because of this filter. Without it the game cannot start |
| `exclude_filter` | `doc/*, scripts/*, Test/_tests.txt` | `Test/*.json` (the test files) **is** included in the Windows build |
| `script_export_mode` | `1` | Scripts exported as compiled bytecode |
| `texture_format/s3tc` | `true` | Desktop texture compression |
| `application/modify_resources` | `false` | The exe's icon and version information are not modified (no rcedit needed). The exe keeps the default Godot icon |
| `codesign/enable` | `false` | Not signed |

### Steps

1. Open the project in Godot 3.5.3 and let the import finish.
2. **Project > Export**, select **Windows Desktop**.
3. Click **Export Project**. To keep the repository clean, choose a file under `<output>` instead of the default `./WC.exe`. Changing the path in this dialog is saved into `export_presets.cfg`; do not commit that change unless intended.
4. Choose a debug build ("Export With Debug" checked) or a release build.

### Output

| File | Content |
|---|---|
| `WC.exe` | Godot runtime |
| `WC.pck` | Game data (scenes, scripts, `Sets/*.json`, ...) |

Both files must be distributed together in the same folder.

Differences between debug and release builds, from the code:
- The **Tests** button of the main menu is only shown in the editor or in debug builds (`src/wc/MainMenu.gd`, `_ready`).
- **Options > Tests** is hidden only on HTML5 (`disable_tests` in `CFConst.PER_OS_INTERNAL_SETTINGS`), so it also exists in a Windows release build.

## 3. HTML5 build

### Preset (`export_presets.cfg`, `[preset.0]` "HTML5")

| Setting | Value | Meaning |
|---|---|---|
| `export_path` | `web/index.html` | `/web` is listed in `.gitignore` |
| `variant/export_type` | `0` | Regular (non-threaded) web build. The code avoids threads on HTML5 (`CFConst.DISABLE_THREADS`, `OS.get_name() == "HTML5"` checks) |
| `include_filter` | `*.json, *.txt` | Same requirement as Windows |
| `exclude_filter` | `doc/*, scripts/*, Test/*` | Tests are not included |
| `vram_texture_compression/for_desktop` | `true` | Desktop texture compression only (`for_mobile=false`) |

Features disabled on HTML5 by the code (`CFConst.PER_OS_INTERNAL_SETTINGS["HTML5"]`): multiplayer, mods, tests. The exit button toggles full screen instead.

### Steps

1. **Project > Export**, select **HTML5**.
2. Click **Export Project** and choose `<output>/web/index.html` (or keep the default `web/index.html`).

### Output

The export folder contains `index.html` and the files it loads, including `index.js`, `index.wasm` and `index.pck`, plus icon and helper files generated by Godot. Serve the whole folder; opening `index.html` directly from the file system does not work.

## 4. Running the HTML5 build locally (Python `http.server`)

Requires Python 3.

```
cd <output>/web
python -m http.server 8000
```

Then open `http://localhost:8000/` in a browser. Stop the server with `Ctrl+C`.

- The build is non-threaded (`variant/export_type=0`), so no special HTTP headers (cross-origin isolation) are needed.
- The game still needs Internet access (see section 7).

## 5. Automated tests (TestSuite)

The test suite is an integration test that plays scripted actions in the real game and compares the final game state with the expected state. Tests are JSON files in `Test/` named `test_*.json`.

### Choosing the tests

- If `Test/_tests.txt` exists, only the files listed in it are run: one file name per line, lines containing `#` are skipped. This file is listed in `.gitignore`.
- Otherwise all `test_*` files in `res://Test/` and `user://Test/` are run. Files with `fanmade` in their name are skipped unless fan-made sets are enabled.
- Tests are filtered by category. A test without `test_conditions.bug_type` belongs to `sanity`.

### Running from the command line

```
<godot> --path <project> --run-tests --test-quit-when-done
```

- `--run-tests[=filters]`: starts the test suite once the main menu has loaded (default filter: `sanity`; e.g. `--run-tests=all,-scenario`).
- `--test-quit-when-done`: quits after the results file is written.
- Other options (`--test-shards=N`, `--test-shard=i/N`, `--test-hide-workers`, `--no-render`) are documented at the top of `src/wc/data/TestShards.gd`.

Example for a single test: put `test_1p_2_attachements.json` alone in `Test/_tests.txt`, then run the command above.

### Running from the game

- Main menu **Tests** button (editor or debug build only): runs the `sanity` tests. It runs in one instance if `Test/_tests.txt` exists, otherwise in parallel instances.
- **Options > Tests**: runs the option selected in the drop-down (`All -cant_repro`, `Sanity`, `Scenario`, `All`).
- Multiplayer tests: start a 2-player game with two Godot instances and run **Options > Tests** on the host. Tests with fewer than 2 heroes are skipped in multiplayer (see README).

### Results

The results are written to `user://test_results_<player_id>.txt` (`test_results_1.txt` for a single-player run; parallel worker instances add a `_shard<i>` suffix). With the default project settings, `user://` on Windows is:

```
%APPDATA%\Godot\app_userdata\WC\
```

The file contains, in this order: `SUCCESS!` or `FAILED!`, the skipped, failed and passed lists, the array comparison warnings, and for failures the expected and actual JSON with an action trace.

**Array comparison warnings** are information only. They do not change PASS/FAIL. A warning means that the actual array (for example a hand) has more items than the expected array in the test's `end` section, so the extra items were not checked. Example:

```
array comparison warnings (actual longer than expected, extra items not checked): 1 test(s)
	res://Test/test_1p_encounter_stampede_vs_spider_sense_backflip.json
		(board/hand1) expected 1 item(s), got 2, not checked: Jessica Jones #01059
```

| Item | Environment | How |

| `test_1p_2_attachements.json`: PASS, 0 warnings | Godot 3.5.3, command line, single test | Automated test |
| `test_1p_2_attachements.json`: PASS | Godot 3.5.0, before and after the TestSuite warning change | Automated test |
| `test_1p_encounter_stampede_vs_spider_sense_backflip.json`: PASS with 1 warning (`board/hand1`); PASS with the original TestSuite too | Godot 3.5.0, single test | Automated test |
| Windows build (`WC.exe` + `WC.pck`) exported and played | Godot 3.5.3 | Manual check |
| HTML5 build exported and played locally through `python -m http.server` | Godot 3.5.3 | Manual check |
| Building with the repository's export presets, with only `application/modify_resources=false` changed | Godot 3.5.3 | Manual check |

Engine messages seen on every automated run, with no effect on the results: `Resumed function 'check_for_new_release()' after yield, but script is gone` (`MainMenu.gd`; the main menu is freed while waiting for the version check) and leak warnings at exit (`ObjectDB instances leaked`, `Resources still in use`, `MemoryPool allocs in use`).

### Not verified yet

## 7. External services and checks before public distribution

### External dependencies (from the code)

Card images are **not** included in the builds. They are downloaded on first start and stored in `user://` (README: "you will need an Internet connection in this early step").

| Purpose | Source in code | Hosts |
|---|---|---|
| Card definitions (`database` setting) | `CFConst.DEFAULT_SETTINGS` | `https://marvelcdb.com/api/public/cards/*.json` |
| Decks | `decks_base_url`, `decks_base_url_backup` | `https://marvelcdb.com/api/public/...` |
| Card images | `CardImageDownloader` default servers, can be overridden by the remote config | includes `marvelcdb.com`, `marvel.champions-digital-game.com`, an `r2.dev` bucket, `github.com` |
| Remote config | `CFConst.SERVER_REMOTE_CONFIG_URL` + `server` setting | `https://wololo.net/wc/resources/remote_settings.json` |
| Multiplayer lobby | `lobby_server` setting | `https://wololo.net/wc/lobby.php` |
| New version check | `CFConst.VERSION_CHECK_URL` | GitHub API, `frwololo/warnel-chawpiovs` releases |
| HTML5 download proxy | `FileDownloader` (`use_proxy` on HTML5), `proxy_url` setting | `https://wololo.net/wc/wc_proxy.php`, only for the hosts in `allowed_by_proxy` |

On HTML5 all downloads go through the original author's proxy. The HTML5 build therefore depends on that server. The code also loads `res://mods/images.zip` on HTML5 (`CFControlExtended.gd`). There is no `mods/` folder in this repository.

### Before a public release

- **Rights:** this is a fan-made game based on Marvel Champions (README: "not affiliated with, endorsed by, or sponsored by Fantasy Flight Games"). The repository has no LICENSE file. Check the original repository's terms before redistributing builds.
- **Servers:** the builds rely on the original author's servers (`wololo.net`) and on third-party image hosts. Check that this use is acceptable, and that these servers can handle the traffic of a new release.
- **Version:** check `GAME_VERSION` / `BUILD_NUMBER` in `src/wc/CFConst.gd`. The version check compares against the original repository's GitHub releases.
- **Tests in the Windows build:** decide whether `Test/*.json` should stay in the Windows package (`exclude_filter`).
- **Unsigned exe:** Windows SmartScreen may warn users. The exe has no custom icon or version information (`modify_resources=false`).
- **Regression:** run at least the `sanity` suite with Godot 3.5.3 before a release (not done yet, see section 6).
